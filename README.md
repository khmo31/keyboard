# 메이플스토리 하드웨어 사냥 매크로 — 설계도

> **버전:** 1.1 | **작성일:** 2026-08-12 | **상태:** 설계 완료, USB Host Shield V560 도착

---

## 1. 아키텍처 개요

### 1.1 설계 원칙

- **단일 USB HID 엔드포인트**: 실제 키보드 입력 + 매크로 입력을 하나의 USB 장치로 통합 → 안티치트가 입력 소스를 구분 불가능
- **하드웨어 레벨**: PC에는 표준 USB 키보드로 인식. 소프트웨어 탐지 불가
- **반자동**: 룬 해제 / 거짓말 탐지기는 사람이 직접 처리. 사냥 루틴만 자동화
- **QMK 펌웨어**: 전 세계 커스텀 키보드 수만 대가 사용하는 검증된 오픈소스 펌웨어. 비정상 USB 패턴 없음

### 1.2 전체 구성도

### 2.2 핀 연결표 — USB Host Shield V560 (ICSP 2×3 헤더)

**⚠️ V560은 Arduino Shield 폼팩터다. SPI는 보드 가장자리의 ICSP 2×3 헤더로 연결한다.**

```
ICSP 2×3 헤더 (핀 1에 △ 마크 있음. 핀 1이 MISO)

         ┌──────────┐
   MISO  │1 ●    2│  VCC (5V)
    SCK  │3 ●    4│  MOSI
  RESET  │5 ●    6│  GND
         └──────────┘
```

| ICSP 핀 | 신호 | → | Pico GPIO | Pico 물리핀 | 설명 |
|---------|------|---|-----------|------------|------|
| ICSP-1 | MISO (SPI 수신) | → | **GP16** (SPI0 RX) | 21 | Shield → Pico 데이터 |
| ICSP-2 | VCC (5V) | → | **VBUS** | 40 | 5V 전원 |
| ICSP-3 | SCK (SPI 클럭) | → | **GP18** (SPI0 SCK) | 24 | SPI 클럭 |
| ICSP-4 | MOSI (SPI 송신) | → | **GP19** (SPI0 TX) | 25 | Pico → Shield 데이터 |
| ICSP-5 | RESET | → | **GP15** | 20 | MAX3421E 리셋 (Active Low. 사용하지 않으면 3.3V에 풀업) |
| ICSP-6 | GND | → | **GND** | 38 | 접지 |

**[택트 스위치]**
| 스위치 핀 | → | Pico GPIO | Pico 물리핀 |
|-----------|------|-----------|------------|
| 스위치 다리 1 | → | GP20 | 26 |
| 스위치 다리 2 | → | GND | 28 |

### 2.3 ⚠️ 솔더 점퍼 브릿지 — 조립 전 필수!

**V560 클론 보드는 출하 시 3개의 솔더 점퍼가 열려 있다. 이걸 브릿지하지 않으면 보드가 완전 무반응이다.**

| 점퍼 위치 | 연결 | 설명 |
|-----------|------|------|
| 3.3V 패드 (좌측) | 브릿지 | MAX3421E 칩 로직 전원 |
| 5V 패드 (좌측) | 브릿지 | 5V 레벨 시프터 전원 |
| VBUS PWR → 5V (USB 포트 근처) | 브릿지 (5V 선택) | USB 장치에 5V 전원 공급. **절대 3.3V 선택 금지** |

**방법:** 인두로 두 패드를 하나의 솔더 블롭으로 연결하면 된다. 납땜 후 멀티미터로 통전 확인할 것.

### 2.4 Pico 물리 핀맵 (참고)

```
         ┌──────────────────────────┐
    VBUS │40 ●                  ● 21│ GP16 (SPI0 RX/MISO)
   VSYS  │39 ●                  ● 22│ GP17 (SPI0 CSn/SS)
    GND  │38 ●                  ● 23│ GND
    3V3  │37 ●                  ● 24│ GP18 (SPI0 SCK)
          │   ●                  ●   │
  GP20    │26 ●                  ● 25│ GP19 (SPI0 TX/MOSI)
    GND   │28 ●                  ● 27│
         └──────────────────────────┘

* 물리 핀 번호는 Pico 보드 실크스크린 기준.
  GPxx = GPIO 번호 (소프트웨어에서 사용)
```

### 2.5 조립 순서

**0. [필수] 솔더 점퍼 브릿지 (납땜)**
   - 2.3절의 솔더 점퍼 3개를 인두로 브릿지
   - 멀티미터 통전 모드로 각 점퍼가 연결되었는지 확인

1. **V560 Shield를 브레드보드에 장착**: ICSP 헤더가 브레드보드 중앙을 향하게
2. **Pico를 브레드보드에 장착**: USB 포트가 바깥쪽을 향하게, Shield와 5~10cm 거리
3. **ICSP ↔ Pico 점퍼 와이어 연결**: 위 핀 연결표에 따라 6개 와이어 연결
   - ICSP 핀 1(△ 마크)부터 순서대로: MISO→GP16, VCC→VBUS, SCK→GP18, MOSI→GP19, RESET→GP15, GND→GND
   - **⚠️ 추가: SS(CS) 핀** — ICSP 헤더에 SS가 없으므로 V560의 D10 핀(Digital 헤더)을 Pico의 GP17에 연결 (점퍼 와이어 1개 추가, 총 7개)
4. **RESET 핀**: 사용하지 않을 경우 GP15를 3.3V에 풀업 (10kΩ 저항 권장). 또는 GP15를 GPIO 출력으로 설정해 LOW→HIGH 순서로 리셋 가능
5. **택트 스위치 연결**: GP20 ↔ GND. 브레드보드 빈 공간에 꽂고 점퍼 와이어 2개로 연결
6. **전원 투입 전 점검**: 모든 연결이 핀 연결표대로 되어 있는지 멀티미터로 통전/단락 확인

## 3. 소프트웨어 설계

### 3.1 QMK 펌웨어 설정

**필요 도구:**
- QMK CLI (`pip install qmk`)
- ARM GCC 툴체인 (`sudo apt install gcc-arm-none-eabi`)

**설정 파일 (config.h):**

```c
// VID/PID 스푸핑 — 실제 키보드 제조사 정보로 위장
#define VENDOR_ID       0x046D   // Logitech
#define PRODUCT_ID      0xC33C   // G 시리즈
#define MANUFACTURER    "Logitech"
#define PRODUCT         "USB Keyboard"

// USB 설정
#define USB_POLLING_INTERVAL_MS 1  // 1ms 폴링 (1000Hz)

// 매트릭스 설정 (버튼 1개만 사용)
#define MATRIX_ROWS 1
#define MATRIX_COLS 1

// 매트릭스 핀
#define MATRIX_ROW_PINS { GP20 }  // 택트 스위치
#define MATRIX_COL_PINS { GP21 }  // 사용 안 함 (더미)

#define DIODE_DIRECTION COL2ROW
```

### 3.2 키 바인딩 (keymap.c)

| 물리 버튼 | 기능 | 동작 |
|-----------|------|------|
| GP20 (택트 스위치) | 사냥 시작/정지 토글 | F3 키코드 전송 → QMK에서 가로채서 macro engine ON/OFF (PC로 전송 안 함) |

**메이플스토리 인게임 키 설정 (사용자에 맞게 변경):**

| 동작 | 기본 키코드 | QMK 상수 |
|------|-----------|----------|
| 점프 | Alt | `KC_LALT` |
| 주력 공격 스킬 | X | `KC_X` |
| 줍기/상호작용 | Z | `KC_Z` |
| 보조 스킬 (광역/버프) | C | `KC_C` |

### 3.3 매크로 엔진 상태 머신

```
        [IDLE]
          │ F3 토글
          ▼
   ┌───────────────────────────────────────────┐
   │             HUNTING LOOP                  │
   │                                           │
   │  Phase 0: 좌측 이동 + 점프                 │
   │     ├─ LEFT 키 누름 + JUMP 키 누름        │
   │     ├─ 30~80ms 유지 후 릴리즈              │
   │     └─ 400~900ms 대기 → Phase 1            │
   │                                           │
   │  Phase 1: 공격                            │
   │     ├─ ATTACK 키 탭 (50~180ms)             │
   │     ├─ Variant 0: 단일 공격 → Phase 2      │
   │     ├─ Variant 1: 이중 공격 → Phase 2      │
   │     └─ Variant 2: 공격+줍기 → Phase 3      │
   │                                           │
   │  Phase 2: 우측 이동 + 점프                 │
   │     ├─ RIGHT 키 누름 + JUMP 키 누름        │
   │     ├─ 30~80ms 유지 후 릴리즈              │
   │     └─ 400~900ms 대기 → Phase 1            │
   │                                           │
   │  Phase 3: 줍기                            │
   │     ├─ LOOT 키 탭                         │
   │     └─ 200~1500ms 대기 → Phase 2           │
   │                                           │
   │  [비동기]                                  │
   │   ├─ 보조 스킬: 5초 쿨다운마다 C 키         │
   │   ├─ 유휴 행동: 10분마다 30% 확률          │
   │   │   엔터 → 랜덤키 → 엔터 (채팅 노이즈)    │
   │   └─ Variant 순환: 3종 패턴               │
   └───────────────────────────────────────────┘
```

### 3.4 타이밍 설계 (탐지 회피)

| 파라미터 | 최소값 | 최대값 | 단위 | 근거 |
|----------|--------|--------|------|------|
| 이동 간격 | 400 | 900 | ms | 인간 반응 속도 + 지형 이동 |
| 공격 딜레이 | 50 | 180 | ms | 스킬 애니메이션 + 입력 버퍼 |
| 줍기 딜레이 | 200 | 1500 | ms | "바로 줍기" = 봇 시그니처 |
| 보조 스킬 쿨다운 | 5000 | - | ms | 버프 지속 시간에 맞춰 조정 |
| 채팅 노이즈 간격 | 600000 | - | ms | 10분. 30% 확률로 실행 |
| Variant 패턴 | 3 | - | 종류 | 단조로운 반복 회피 |

**모든 딜레이는 `rand() % (MAX - MIN) + MIN` 으로 랜덤화. ±50ms 인간 편차 범위 내.**

## 4. 펌웨어 빌드 & 플래싱

### 4.1 QMK 환경 설정

```bash
# QMK CLI 설치
pip install qmk

# ARM 툴체인 설치
sudo apt install gcc-arm-none-eabi

# QMK 설정
qmk setup
```

### 4.2 펌웨어 컴파일

```bash
# 프로젝트 디렉토리에서
qmk compile -kb handwired/pico_hunt -km default
# 출력: handwired_pico_hunt_default.uf2
```

### 4.3 Pico에 플래싱

1. Pico의 BOOTSEL 버튼을 **누른 상태로** USB 케이블을 PC에 연결
2. RPI-RP2 드라이브로 마운트됨
3. `.uf2` 파일을 드래그 앤 드롭
4. Pico가 자동 재부팅 → 키보드로 인식됨

### 4.4 디버깅

```bash
# QMK 콘솔 (키 입력 로그)
qmk console

# HID 디바이스 확인
lsusb | grep Logitech
```

## 5. 안티치트 회피 전략

### 5.1 기술적 방어

| 탐지 벡터 | 대응 | 구현 방식 |
|-----------|------|----------|
| **USB HID 소스 분리** | 단일 HID 엔드포인트 | Pico가 모든 입력 통합 |
| **VID/PID 시그니처** | 스푸핑 | config.h에서 Logitech으로 위장 |
| **USB 패턴 이상** | QMK 표준 스택 | 커스텀 USB 드라이버 사용 안 함 |
| **프로세스 탐지** | 해당 없음 | PC에 소프트웨어 설치 안 함 |
| **메모리 변조** | 해당 없음 | 게임 메모리 접근 안 함 |

### 5.2 행동적 방어

| 탐지 벡터 | 대응 | 구현 위치 |
|-----------|------|----------|
| **타이밍 일정** | 모든 딜레이 랜덤화 | `matrix_scan_user()` |
| **패턴 반복** | 3종 Variant 순환 | `hunt_variant` 상태 |
| **장시간 연속** | 8~10시간 제한 권장 | 사용자 수동 관리 |
| **채팅 없음** | 무작위 키 노이즈 | `IDLE_CHECK` 루틴 |
| **전리품 즉시 획득** | 0.2~1.5초 지연 | Phase 3 랜덤 딜레이 |
| **맵 고정** | 주기적 맵 변경 | 사용자 수동 관리 |

### 5.3 NGS 특이사항 (메이플스토리 전용)

- 룬(↑↓←→) / 거짓말 탐지기(숫자) → **사람이 직접 해제.** Phase 2 (OpenCV + 캡처카드) 필요
- 엘리트 몬스터 → 자동 전투로 처리 가능
- NGS는 `WM_INPUT`의 `hDevice` 핸들로 디바이스 추적 가능성 있음 → 단일 HID로 우회

## 6. 테스트 계획

### 6.1 1단계: 하드웨어 검증 (30분)

- [ ] 모든 핀연결 멀티미터 통전 테스트
- [ ] Pico USB 연결 → PC에서 "USB Keyboard"로 인식 확인 (`lsusb` / 장치 관리자)
- [ ] 택트 스위치 눌러서 F3 신호 확인 (`qmk console`)
- [ ] MAX3421E 전원 인가 확인 (5V, 3.3V)

### 6.2 2단계: 키 입력 검증 (1시간)

- [ ] 메모장에서 택트 스위치 토글 → F3 신호 정상 확인
- [ ] 실제 키보드로 타자 입력 → Pico 거쳐서 PC에 정상 전달 확인
- [ ] 매크로 엔진 ON → LEFT/RIGHT/JUMP/ATTACK 시퀀스 확인
- [ ] 매크로 엔진 OFF → 실제 키보드만 전달 확인
- [ ] Variant 스위치 → 3종 패턴 순환 확인

### 6.3 3단계: 게임 내 검증 (2~3시간, 무고밸류 계정)

- [ ] 무고밸류 계정(또는 테스트 서버)에서 사냥 시작
- [ ] 1시간 연속 사냥 → 룬/거탐 출현 시 수동 해제
- [ ] NGS 경고 발생 여부 모니터링
- [ ] 타이밍 랜덤화 효과 확인 (패턴 반복 시각 확인)
- [ ] Variant 3종 전환 테스트
- [ ] 2시간 후 정상 로그아웃

## 8. 향후 확장 (Phase 2 — 비전 기반 완전 자동)

Phase 1(현재)에서는 룬/거탐은 사람이 처리한다. 장기적으로 다음을 추가할 수 있다:

```
[Raspberry Pi 4] ──USB──► [Pico (HID)] ──USB──► [게임 PC]
      ↑ HDMI
  [HDMI 캡처 카드] ← [게임 PC GPU]
```

- **OpenCV**: 화면에서 룬 화살표, 거탐 숫자, HP/MP 바, 미니맵 인식
- **Pi ↔ Pico 시리얼 통신**: UART로 명령 전송
- **룬 자동 해제**: 화살표 패턴 OCR → 해당 키 입력
- **거탐 자동 해제**: 숫자 OCR → 해당 키 입력

## 부록 A. 문제해결

### V560 특이 문제

| 문제 | 원인 가능성 | 해결 |
|------|-----------|------|
| **보드 완전 무반응 (전원 안 들어옴)** | 솔더 점퍼 미브릿지 | 3개 점퍼(3.3V, 5V, VBUS PWR) 납땜 확인. 멀티미터로 통전 테스트 |
| **board_qc 통과했는데 USB 장치 인식 안 됨** | MAX3421E USB PHY 불량 | IC 칩의 디지털 부분은 정상이나 아날로그(USB 트랜시버) 불량. 교환/RMA 필요 |
| **마우스 LED 안 켜짐 → 전원 문제로 오판** | 최신 마우스는 USB 열거 전까지 LED OFF | **마우스 LED는 전원 표시기가 아니다.** USB 전압계로 Shield 포트의 5V를 직접 측정할 것 |
| **SPI 통신 안 됨** | SS 핀(D10) 미연결 | V560 ICSP 헤더에 SS 없음 → D10을 Pico GP17에 별도 연결 필수 |

### 공통 문제

| 문제 | 원인 가능성 | 해결 |
|------|-----------|------|
| PC가 Pico를 인식 못 함 | USB 케이블이 전원 전용 | 데이터 전송 가능 케이블로 교체 |
| 키 입력이 안 됨 | SPI 연결 불량 | 점퍼 와이어 재장착, GND 공통 확인 |
| 매크로 ON인데 입력 없음 | `matrix_scan_user()` 미호출 | QMK 설정 확인 |
| NGS 경고 발생 | 타이밍 패턴 반복 탐지 | 딜레이 범위 2배로 확장 |
| Pico 과열 | 5V 과전압 | Shield 쪽 3.3V 레귤레이터 확인 |
